## Standing lessons and hard constraints

- **`litebox::sync::RwLock::try_read`/`try_write` FAIL WHEN A WRITER IS MERELY QUEUED** (`litebox/src/sync/rwlock.rs`): ONE thread parked in a blocking `descriptor_table_mut()` makes every `try_descriptor_table()` fail forever and the per-tick socket sweep a silent no-op in that process. `Network::close` is the only blocking whole-table writer. `iter_nowait`/`iter_mut_nowait` (`fd.rs`) skip an entry on `try_read` OR `try_write` failure. Dead-holder recovery needs the owner thread DEAD - a parked one is never recovered.
- **THE CROSS-PROCESS FORK'S COPY PLAN IS GRANULE-WIDENED AND MERGED** (`process.rs`: `GRANULE = 0x1_0000`; each region is widened to its enclosing granule and touching spans coalesce). A group is reserved in the child with `VirtualAlloc2` + `MEM_ADDRESS_REQUIREMENTS` at the parent's own base, so a group base MUST stay granule-aligned or Windows answers `ERROR_INVALID_PARAMETER` (87); `read_source_bytes` walks a group page at a time and zero-fills only UNREADABLE padding. **NOTHING IN `litebox/src/mm` ZEROES A FRESH PAGE - the guarantee is Windows `MEM_COMMIT`, and `MEM_COMMIT` on an ALREADY-COMMITTED page does not re-zero**, so a range a fork group committed once can hand a later guest `mmap` stale parent bytes (`PageManager::reset_pages` is the `MADV_DONTNEED` path, not the fresh-mmap one). **`vma_layout()` zips `ranges`/`flags`/`executable`/`is_file_backed` POSITIONALLY - filter ALL of them or NONE**; filtering `ranges` alone shifts every later region onto its neighbour's flags (the first `VM_DONT_FORK` fix attempt did exactly that).
- **A GUEST PACKET TO `127.0.0.0/8` OR TO `GUEST_IP_ADDR` IS LOOPED IN-PROCESS** (`packet_targets_guest_loopback`, `platform/net.rs:1010`): a guest's `127.0.0.1:<port>` NEVER reaches the host's published listener (so a loopback refusal cannot be host-side) and **an instrument in `platform` never sees such a packet**. **`buffers.occupancy()`: `data_granted` is the pool's CAPACITY actually granted (512 healthy, halved under arena pressure), `data_used` the slots in use - `granted` is NOT "in use"**.
- Guest-reachable code returns an errno, never a panic (the host process IS the whole session). Refusal errno is contract: EPERM degrades, EINVAL/ENOSYS fails hard. `LITEBOX_DUMP_FRAMES=1` is the only trustworthy `--gui` visual check. Never subtract timestamps across a parent and a fork-child log.
- **A `TypedFd` index is valid only against the `Descriptors` that inserted it, and only for its own subsystem.** Shared-memory structs hold no process-relative pointers; a per-process object cannot be another process's delivery target. **A `SharedUnixAddrPresenceTable`-shaped table needs every write path mirrored, and no per-tick sweep may DROP another process's object.** **A backlog slot of a listening port is reachable by NOTHING but `accept`** - no fd, no proxy. **A port with no slot in LISTEN refuses every SYN** while its accepted connections keep streaming. **`(dev,ino)` is cross-process-stable for IMAGE files ONLY** - key shared registries on `(dev,path)`.
- **Shared unix connection slots are counted by HOST-PROCESS LIVENESS**: a hold never given back keeps its slot OCCUPIED + `held_live` for the donor process's whole life. 4096 slots; chrF15's 11,458 refusals in 64 s - the counter SPINS once full.
- Cross-process fork: carried = pipes/regular files/eventfds/pty/unix sockets + INET + `MAP_SHARED`; dropped = pty fds, non-INET cloexec fds. Slots (`CROSS_PROCESS_FORK_SLOT_COUNT` 6) gate the spawn, fail open after 8 s, freed at STARTUP-COMPLETE; the env var is PRESENCE-CHECKED (`=0` still ENABLES it). **`fork_carry` holds the child's end under the PARENT's pid until the child is live - CONTROL: a long-lived child must make the parent's `recv` TIME OUT, not return `b''`.**
- **Lazy file map**: chunks >= `MIN_LAZY_LEN` (256 KiB) are armed `PAGE_NOACCESS` and VEH-filled from a `'static` slice keyed by OCI LAYER INDEX. A guest reads guest strings through a bare host-side dereference with NO validation: `Some("")` = a real 0x00 byte, `None` = the read faulted.
- **`ps -eo pid,args` is INVALID for chromium's children - every one reports `--type=zygote`**; `/proc/<pid>/cmdline` and `comm` are EMPTY, so `chrdesk55.sh`'s `gpuproc=`/`rendproc=` reads 0 EVEN WHEN CHROMIUM IS PAINTING - use CDP or an xwd (same for selkies: `[s] HOLD selkpid=none` is a census artifact, `code=200` beside it is the evidence). **A DEAD FORK CHILD CAN STAY LISTED IN ANOTHER PROCESS'S `ps`.**
- Logs: default `warn,...fork_verify=error`; verbosity from `LITEBOX_LOG`, not `RUST_LOG`; `litebox_util_log::warn!` takes a single literal with inline captures; **its `debug!` fields take `&str`, not an owned `String`** (bind a local, pass `.as_str()`). **Timestamps are PER-PROCESS UPTIME; `.err` lines carry ANSI escapes** (`\x1b\[[0-9;]*m`).
