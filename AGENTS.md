## How to run and drive it (prose: `docs/HARNESS-LESSONS.md`)

- **No WSL, no hypervisor, ever** - native Win32 exe. **ALWAYS launch through `.wfgy/guest2.ps1`** (a hand-written launch runs with fork OFF - `575f0e2`): `-Script <sh> -Run <name> -Secs <n> [-Publish h:g] [-ExtraEnv "K=V;K2=V2"] [-Exe]`. Its `Stop-Litebox` kills EVERY process under `target\release`, so B while A is live kills A; a background "failed exit code 128" is that `taskkill`, NOT the run - `.wfgy/<run>.out` is authoritative. **NEVER run a probe while another run is live.**

- **A HOST-SIDE HELPER CANNOT POLL `.wfgy/<run>.out`**; bash `grep -a` DOES read a runner-held `.out`/`.err`. **Use a FIXED delay - chrF30 reached HOLD at ~70 s, probe from ~100 s.** **STREAM a crashing guest process's stderr - never redirect it to a file.**

- **HOST RESOURCE GATE (stated only here)**: a background shell DIES AT ITS 30 MIN CAP (keep `-Secs` <=1500) and is REAPED WHEN HOST MEMORY IS CRITICALLY LOW, INCLUDING a `cargo build` (~1.3 GB free) - never re-read a killed build as a compile error. **A REAPED SHELL IS NOT A DEAD GUEST.** See NEVER-KILL.

- Cheap repro: `target/release/...exe -Z --oci-image docker.io/library/debian:stable-slim -- /bin/bash -c '<script>'`; single quotes only inside `-c`. **A RAW (not `guest2.ps1`) RUN RE-RESOLVES THE MANIFEST AND OVERWRITES THE PIN** - set `LITEBOX_OCI_USE_LAST_RESOLVED=1` (+ `MSYS_NO_PATHCONV=1`), then `md5sum` the pin against `OLDGOOD.json`. **Build ONLY `cargo build --release -p litebox_runner_linux_on_windows_userland`**; **never pipe a build through `tail`**; cargo cannot relink while a runner holds the exe (`os error 5`) - sweep first. **`cargo check -p litebox_shim_linux` alone FAILS with `cannot find tracing in __private`.** **Check an instrument is in the binary by its OUTPUT SHAPE, never the `EXE -nt <src>` gate.**
