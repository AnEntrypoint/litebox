## Standing lessons and hard constraints (mechanism: `docs/HARNESS-LESSONS.md`)
- **ORPHANED FORK CHILDREN ARE THE FREEZE MECHANISM AND THEY FORGE RESULTS.** `timeout -s KILL` kills ONLY the parent runner; litebox's fork children survive (18 orphans once drove load to 25/92/109 and MemAvailable to 2.5 GB) and **a starved run reports the same zeros as a fixed one** — **0 is not evidence unless the arm actually ran; record guest pid count and log size beside every counter**. **Sweep `pkill -KILL -f 'lbxrun'` at the START and END of every script — by the private name** (`comm` is `lbxrun`); **never `pkill -f litebox_runner`** — that kills other tracks. Gate each arm on 1-min load < 4 and MemAvailable > 2 GB. On Windows sweep by CIM (`taskkill` fails on orphaned fork children).
- **HOLD `/tmp/lbx/.runner-lock` ONLY AROUND AN ACTUAL RUN** — `mkdir` immediately before launching, `rmdir` immediately after. A session-long lock once sat idle 77 minutes and starved another track.
- **A `LITEBOX_*_OFF` SWITCH IS PRESENCE-CHECKED: `=0` MEANS OFF.** `env_flag` = `var_os(name).is_some_and(|v| !v.is_empty())` (`linux lib.rs:3618-3620`); every call site is `!env_flag(...)`, so **RULE: ON = unset, OFF = `=1`, never `=0`.** Two ways a BOTH-WAYS pair comes back identical, both seen here: a **stale binary** (**a `diag-*` count only means something if the binary that ran carried that `warn!`**) and **a concurrent `cargo check`/build stealing the box** (uz8/uz9 voided). **NEVER build or type-check while an arm is running.**
- **The rest of the standing rules are verbatim in `docs/AGENTS_ARCHIVE_2026-10-10d.md` (the `-10c` text) and `docs/HARNESS-LESSONS.md` — read them before a run**: RwLock `try_read`/`try_write` fail when a writer is merely QUEUED · the fork copy plan is GRANULE-widened (`0x1_0000`), nothing in `litebox/src/mm` zeroes a fresh page, `vma_layout()` zips POSITIONALLY · a guest packet to `127.0.0.0/8` is looped in-process · **NO NETWORK in this container's guest** (`send_ip_packet` `unimplemented!`); only stdout/stderr and `--export-writable-layer` reach the host · a guest AF_UNIX socket never becomes a host fd; `--insert-file` is `unimplemented!()`; **spill is INERT HERE** · a `TypedFd` is valid only against its own `Descriptors`; no sweep may DROP another process's object; a backlog slot is reachable by nothing but `accept`; `(dev,ino)` is stable for IMAGE files ONLY · writes are invisible until the process is REAPED · log traps: `LITEBOX_LOG` not `RUST_LOG`, `debug!` fields take `&str`, PER-PROCESS UPTIME, `.err` ANSI, `tag=`/`dtag=` do not identify a host process, census `0:L:0` cannot prove a port is armed, **`ps -eo pid,args` is INVALID for chromium's children** · **4 CPUs / 7.8 GB: one runner at a time, `nice -n 19`, check host RAM first**.
- Guest-reachable code returns an errno, never a panic (the host process IS the whole session). Refusal errno is contract: EPERM degrades, EINVAL/ENOSYS fails hard. `LITEBOX_DUMP_FRAMES=1` is the only trustworthy `--gui` visual check. Never subtract timestamps across a parent and a fork-child log.
