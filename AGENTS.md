- THE CROSS-PROCESS FORK'S COPY PLAN IS GRANULE-WIDENED AND MERGED (`process.rs`: `GRANULE = 0x1_0000`; a group base MUST stay granule-aligned or Windows answers 87). NOTHING IN `litebox/src/mm` ZEROES A FRESH PAGE - the guarantee is Windows `MEM_COMMIT`.
- A GUEST PACKET TO `127.0.0.0/8` OR TO `GUEST_IP_ADDR` IS LOOPED IN-PROCESS (`phy.rs:166`): a guest's `127.0.0.1:<port>` NEVER reaches the host's published listener. `LITEBOX_DUMP_FRAMES=1` is the only trustworthy `--gui` visual check.
- A `TypedFd` index is valid only against the `Descriptors` that inserted it, and only for its own subsystem. No per-tick sweep may DROP another process's object. A port with no slot in LISTEN refuses every SYN while its accepted connections keep streaming. `(dev,ino)` is cross-process-stable for IMAGE files ONLY - key shared registries on `(dev,path)`.
- A process's writes are invisible to everyone until it is REAPED, not when it closes; a fork child's writes reach the parent only on `wait4`. Carried: pipes/files/eventfds/pty/unix sockets + INET + `MAP_SHARED`; dropped: pty fds, non-INET cloexec fds; slots (6) gate the spawn, fail open after 8 s. `fork_carry` holds the child's end under the PARENT's pid until the child is live - CONTROL: a long-lived child must make the parent's `recv` TIME OUT, not return `b''`. `file_spill.rs` - extend `SPILLED_PREFIXES`, do NOT add `/tmp/`.
- Child exit: `waitpid(-1)` sees only children registered in THIS host process -> ECHILD; SIGCHLD is dispatched only at `check_for_interrupt`/`prepare_to_run_guest`, so `signalfd` never wakes but `pidfd_open` does. Census is `local_port:state:remote_port`, a listening slot `0:L:0` - it CANNOT prove a port is armed.
