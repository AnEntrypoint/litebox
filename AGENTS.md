## Standing lessons and hard constraints (mechanism: `docs/HARNESS-LESSONS.md`)
- **ORPHANED FORK CHILDREN ARE THE FREEZE MECHANISM AND THEY FORGE RESULTS.** `timeout -s KILL` kills ONLY the parent runner; litebox's fork children survive (18 orphans once drove load to 25/92/109) and **a starved run reports the same zeros as a fixed one** — **0 is not evidence unless the arm actually ran; record guest pid count and log size beside every counter**. **Sweep `pkill -KILL -f 'lbxrun'` at the START and END of every script — by the private name**; **never `pkill -f litebox_runner`** — that kills other tracks. Gate each arm on 1-min load < 4 and MemAvailable > 2 GB. **`pgrep -f lbxrun` COUNTS THE SHELL RUNNING IT — use `pgrep -x lbxrun`** (a bare `pgrep -c -f` once reported 14 orphans on a box with zero).
- **HOLD `/tmp/lbx/.runner-lock` ONLY AROUND AN ACTUAL RUN** — `mkdir` immediately before launching, `rmdir` immediately after. A session-long lock once sat idle 77 minutes and starved another track.
- **A `LITEBOX_*_OFF` SWITCH IS PRESENCE-CHECKED: `=0` MEANS OFF.** `env_flag` = `var_os(name).is_some_and(|v| !v.is_empty())` (`linux lib.rs:3618-3620`); every call site is `!env_flag(...)`, so **RULE: ON = unset, OFF = `=1`, never `=0`.** Two ways a BOTH-WAYS pair comes back identical, both seen here: a **stale binary** (**a `diag-*` count only means something if the binary that ran carried that `warn!`**) and **a concurrent build stealing the box**. **NEVER build or type-check while an arm is running.**
- **The rest of the standing rules are VERBATIM in `docs/HARNESS-LESSONS.md` and `docs/AGENTS_ARCHIVE_2026-10-10d.md` — read them before a run.** The ones that bite: RwLock `try_read`/`try_write` fail when a writer is merely QUEUED · the fork copy plan is GRANULE-widened (`0x1_0000`) and `vma_layout()` zips POSITIONALLY · **NO NETWORK in this container's guest**; only stdout/stderr and `--export-writable-layer` reach the host · a guest AF_UNIX socket never becomes a host fd · **spill is INERT HERE** · a `TypedFd` is valid only against its own `Descriptors` · a backlog slot is reachable by nothing but `accept` · writes are invisible until the process is REAPED · log traps: `LITEBOX_LOG` not `RUST_LOG`, PER-PROCESS UPTIME, `.err` ANSI, **`ps -eo pid,args` is INVALID for chromium's children** · **4 CPUs / 7.8 GB: one runner at a time, `nice -n 19`, check host RAM first**.
- Guest-reachable code returns an errno, never a panic (the host process IS the whole session). Refusal errno is contract: EPERM degrades, EINVAL/ENOSYS fails hard. `LITEBOX_DUMP_FRAMES=1` is the only trustworthy `--gui` visual check. Never subtract timestamps across a parent and a fork-child log.
