- **ORPHANED FORK CHILDREN ARE THE FREEZE MECHANISM AND THEY FORGE RESULTS.** `timeout -s KILL` kills ONLY the parent runner; litebox's fork children survive (18 orphans once drove load to 25/92/109) and **a starved run reports the same zeros as a fixed one** — **0 is not evidence unless the arm actually ran; record guest pid count and log size beside every counter**. **Sweep `pkill -KILL -f 'lbxrun'` at the START and END of every script — by the private name**; **never `pkill -f litebox_runner`** — that kills other tracks. - **A `LITEBOX_*_OFF` SWITCH IS PRESENCE-CHECKED: `=0` MEANS OFF.** `env_flag` = `var_os(name).is_some_and(|v| !v.is_empty())` (`linux lib.rs:3618-3620`); every call site is `!env_flag(...)`, so **RULE: ON = unset, OFF = `=1`, never `=0`.** Two ways a BOTH-WAYS pair comes back identical, both seen here: a **stale binary** (**a `diag-*` count only means something if the binary that ran carried that `warn!`**) and **a concurrent build stealing the box**. **NEVER build or type-check while an arm is running.**
