## Standing lessons and hard constraints

- **`litebox::sync::RwLock::try_read`/`try_write` FAIL WHEN A WRITER IS MERELY QUEUED** (`litebox/src/sync/rwlock.rs`): ONE thread parked in a blocking `descriptor_table_mut()` makes every `try_descriptor_table()` fail forever and the per-tick socket sweep a silent no-op in that process. Dead-holder recovery needs the owner thread DEAD - a parked one is never recovered.
- **THE CROSS-PROCESS FORK'S COPY PLAN IS GRANULE-WIDENED AND MERGED** (`process.rs`: `GRANULE = 0x1_0000`; regions widened to their enclosing granule, touching spans coalesced). A group is reserved with `VirtualAlloc2` + `MEM_ADDRESS_REQUIREMENTS` at the parent's own base, so a group base MUST stay granule-aligned or Windows answers 87; **NOTHING IN `litebox/src/mm` ZEROES A FRESH PAGE - the guarantee is Windows `MEM_COMMIT`, and `MEM_COMMIT` on an already-committed page does not re-zero**, so a range a fork group committed once can hand a later guest `mmap` stale parent bytes (`PageManager::reset_pages` is the `MADV_DONTNEED` path). **`vma_layout()` zips `ranges`/`flags`/`executable`/`is_file_backed` POSITIONALLY - filter ALL or NONE.**
- **A GUEST PACKET TO `127.0.0.0/8` OR TO `GUEST_IP_ADDR` IS LOOPED IN-PROCESS** (`phy.rs:166`): a guest's `127.0.0.1:<port>` NEVER reaches the host's published listener and **an instrument in `platform` never sees such a packet**. **`buffers.occupancy()`: `data_granted` is the pool's CAPACITY actually granted (512 healthy, halved under arena pressure), `data_used` the slots in use - `granted` is NOT "in use"**.
- Guest-reachable code returns an errno, never a panic (the host process IS the whole session). Refusal errno is contract: EPERM degrades, EINVAL/ENOSYS fails hard. `LITEBOX_DUMP_FRAMES=1` is the only trustworthy `--gui` visual check. Never subtract timestamps across a parent and a fork-child log.
- **A `TypedFd` index is valid only against the `Descriptors` that inserted it, and only for its own subsystem.** **A `SharedUnixAddrPresenceTable`-shaped table needs every write path mirrored, and no per-tick sweep may DROP another process's object.** **A backlog slot of a listening port is reachable by NOTHING but `accept`** - no fd, no proxy. **A port with no slot in LISTEN refuses every SYN** while its accepted connections keep streaming. **`(dev,ino)` is cross-process-stable for IMAGE files ONLY** - key shared registries on `(dev,path)`.
- Shared unix connection slots are counted by HOST-PROCESS LIVENESS: a hold never given back keeps its slot OCCUPIED for the donor process's whole life. 4096 slots - the counter SPINS once full.
- Cross-process fork: carried = pipes/regular files/eventfds/pty/unix sockets + INET + `MAP_SHARED`; dropped = pty fds, non-INET cloexec fds. Slots (6) gate the spawn, fail open after 8 s, freed at STARTUP-COMPLETE; the env var is PRESENCE-CHECKED (`=0` still ENABLES it). **`fork_carry` holds the child's end under the PARENT's pid until the child is live - CONTROL: a long-lived child must make the parent's `recv` TIME OUT, not return `b''`.** **A process's writes are invisible to everyone until it is REAPED, not when it closes** (filecoh4 `read_live` mid=0 final=200).
- **Lazy file map**: chunks >= `MIN_LAZY_LEN` (256 KiB) are armed `PAGE_NOACCESS` and VEH-filled from a `'static` slice keyed by OCI LAYER INDEX. A guest string read is a bare host-side dereference with NO validation: `Some("")` = a real 0x00 byte, `None` = the read faulted.
- **`ps -eo pid,args` is INVALID for chromium's children - every one reports `--type=zygote`**; `/proc/<pid>/cmdline` and `comm` are EMPTY, so `chrdesk55.sh`'s `gpuproc=`/`rendproc=` reads 0 EVEN WHEN CHROMIUM IS PAINTING - use CDP or an xwd (same for selkies: `[s] HOLD selkpid=none` is a census artifact, `code=200` beside it is the evidence). **A DEAD FORK CHILD CAN STAY LISTED IN ANOTHER PROCESS'S `ps`.**
- Logs: default `warn,...fork_verify=error`; verbosity from `LITEBOX_LOG`, not `RUST_LOG`; `warn!` takes a single literal with inline captures; **`debug!` fields take `&str`, not an owned `String`** (bind a local, pass `.as_str()`). **Timestamps are PER-PROCESS UPTIME; `.err` lines carry ANSI escapes** - strip with `sed 's/\x1b\[[0-9;]*m//g'` before counting. **The `tag=`/`dtag=` fields DO NOT identify a host process.** Socket census is `local_port:state:remote_port`; a listening slot is `0:L:0`, so the census CANNOT prove a port is armed.
- Env: `LITEBOX_PROCESS_FORK`, `_LAZY_FILE_MAP`, `_IDLE_TRIM=0`, `_OCI_USE_LAST_RESOLVED`, `_DUMP_FRAMES`, `_PROCESS_FORK_IGNORE_FDS`, `_DIAG_FORK_SHARED_FORCE_FAIL`, `_FLOCK_SHARED_OFF`, `_RECORD_LOCK_SHARED_OFF`, `_PUBLISH`; diagnostics `_LOCKSTALL`/`_WAIT_DUR`/`_MEM_BREAKDOWN`/`_FAULT`/`_WATCHDOG`/`_NO_FAULT_WATCHDOG`/`_NO_EXTERNAL_FAULT_WATCHDOG`/`_FAULT_VQ` (full list `-07c`).
- **Host memory: check host RAM FIRST.** Two stuck `python.exe gcloud.py` deploy loops (the user's - DO NOT kill them) held ~1.6 GB each. gm's browser (2.2 GB **PER INSTANCE**) and its plugkit build (~1 GB) - LEAVE THEM. **A `chrome.exe` storm is usually NOT gm: check the parent - `node.exe C:\dev\train\tools\queue.mjs run` (the user's queue worker) spawns a browser per task, 2 GB in under a minute.** **When free RAM is short there is nothing safe to reclaim - wait.** **That `bun` is not mine to kill.**
- Child exit (prose in `-05b` S10): `waitpid(-1)` sees only children registered in THIS host process -> ECHILD; SIGCHLD is dispatched only at `check_for_interrupt`/`prepare_to_run_guest`, so `signalfd` never wakes but `pidfd_open` does; **a file one host process wrote is invisible to siblings until it exits; a fork child's writes reach the parent only on `wait4`**; `file_spill.rs` - **extend `SPILLED_PREFIXES`, do NOT add `/tmp/`**.
- **gm**: the MCP tool can be disconnected while the daemon is still up - fall back to `curl -s -X POST http://127.0.0.1:8787/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '<json>'` with a `tools/call` body. **`cwd` MUST be FORWARD-slash (`C:/dev/litebox-main`) - backslashes answer `Parse error: Invalid JSON`**; back-to-back calls need `sleep 1`.
